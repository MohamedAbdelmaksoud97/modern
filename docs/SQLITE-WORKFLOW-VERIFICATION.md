# تجربة دورة تشغيل مكتب مودرن على SQLite

بدأت التجربة بقاعدة SQLite جديدة فيها حساب مدير مؤقت واحد. شغّل Playwright نسخة معزولة من تطبيق Next.js الحقيقي على عنوان محلي. استخدمت النسخة نفس الصفحات ونماذج الدخول والملفات واستدعاءات الخادم وقواعد الانتقال، واستُبدلت طبقة الاتصال بقاعدة البيانات فقط. بقيت سجلات التجربة في `.local/sqlite-workflow` دون استخدام إعدادات Supabase أو WAHA.

| الخطوة | ما تم اختباره |
| --- | --- |
| حسابات الموظفين | أنشأ المدير من شاشة الفريق حسابات السكرتارية والمحاسب والمعماري والمدني ورسّام الواجهات ورسّام البلدية ومهندس الإشراف. دخل كل مستخدم بجلسة مستقلة وغيّر كلمة المرور الأولية. |
| الاستقبال والإسناد | أنشأت السكرتارية العميل وحسابه والمشروع وعيّنت مسؤولي المراحل. منع النظام إكمال الاستقبال قبل رفع العقد. |
| المهام | أسندت السكرتارية مهمة مراجعة المخططات للمعماري، ثم نقلها المعماري إلى «مكتملة». لم تظهر المهمة للمدني. |
| التصميم والتسليم | سلّم كل موظف مرحلته من الواجهة بعد رفع المخرجات. مُنع التسليم قبل المستند المطلوب، ومُنع المدني ومهندس الإشراف من فتح المشروع قبل دورهما. |
| البلدية | اختبرت السكرتارية الرفض والعودة لإعداد الملف. لم يعد الملف القديم كافيًا للتسليم. رفع الرسام نسخة جديدة ثم سجّلت السكرتارية القبول وعقد الإشراف. |
| الإشراف والإغلاق | قرأ مهندس الإشراف المستندات السابقة وسجّل ثلاث زيارات. ظهرت الصورة مرتبطة بالزيارة الصحيحة. عاد طلب الإنهاء إلى الإشراف للتصحيح، ثم اعتمدته السكرتارية وأغلقت المشروع. |
| المالية | أصدرت السكرتارية عرضًا بـ 1,200.125 د.ك. وزّع المحاسب النسب 30.125٪ و69.875٪ وسجّل 200.025 د.ك. ظهر في بوابة العميل رصيد 1,000.100 د.ك دون تفاصيل الدفعة المحجوبة. |
| بوابة العميل | دخل العميل برقم الهوية وكلمة المرور الأولية ثم غيّرها. ظهرت المرحلة والرصيد والملف المعماري الذي سمح به المدير، وحُجب الملف المدني. أعاد رابط العرض محتوى الملف المرفوع بالكامل، ورُفض طلب التنزيل المباشر بحالة 403. |
| سجل المراجعة وواتساب | ظهرت العمليات في سجل المراجعة وقائمة انتظار واتساب. تحققت حالة المزود غير المُهيّأ. لم تُرسل رسائل حقيقية. |

نجح سيناريو Playwright النهائي في 19 خطوة. أظهرت قراءة ملف SQLite بعد الاختبار حالة المشروع `completed` في المرحلة 9، واعتماد البلدية وإنهاء الإشراف، و12 مستندًا و3 زيارات و59 حدث تدقيق و32 إشعارًا مؤجلًا في الطابور. سجّل التدقيق إنشاء سبعة موظفين من لوحة المدير وتسعة تغييرات لكلمات المرور. أظهر فحص SQLite `integrity_check` القيمة `ok`. نجح أيضًا فحص TypeScript وESLint.

واجهت الجولة الأولى بطء البناء عند فتح صفحات خادم التطوير. تشغّل أداة الاختبار الآن النسخة المعزولة ببناء الإنتاج وتعيد استخدامه عند تطابق المصدر. كما صححت الجولة التالية انتظار واجهة قرار البلدية. بعد الرفض يختفي النموذج لأن المشروع يعود إلى مرحلة إعداد الملف.

## إعادة التجربة

```sh
npx playwright install chromium
npm run test:workflow:sqlite
node scripts/inspect-sqlite-workflow.mjs <path-to-workflow.sqlite>
```

يطبع الأمر مسار المجلد الذي يحتوي على `workflow.sqlite` و`report/index.html` ولقطات المتصفح. يولّد كل تشغيل حسابات وبيانات تجريبية منفصلة. يفحص SQLite سلوك الصفحات وقواعد التطبيق في البيئة المحلية. يظل اختبار تنفيذ سياسات PostgreSQL على خادم PostgreSQL، ويحتاج إرسال الرسائل الفعلي إلى مزوّد WAHA مربوط.
